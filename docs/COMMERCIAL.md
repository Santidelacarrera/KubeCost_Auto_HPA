## 1. Value Proposition for Enterprises

Traditional autoscalers (such as the native Kubernetes HPA) scale workloads purely on CPU or Memory utilization percentages. This creates two costly problems:
1. **Severe Cloud Overprovisioning:** Workloads run oversized instances "just in case", wasting 30% to 50% of Kubernetes cluster spend.
2. **SLA Violations during Spikes:** CPU throttling can occur even when memory is abundant, degrading p99 latency without triggering horizontal scale in time.

**KubeCost Auto-HPA** bridges FinOps and Platform Engineering by introducing **Unit Economics Scaling**:
- It evaluates the financial cost per request served (`$/request`) against strict p99 latency SLOs.
- It dynamically shrinks workloads when latency is safe and expands them when demand surges.
- It leverages Kubernetes in-place pod resizing without disruptive rolling updates.
- It safely automates Spot instance draining with zero downtime.
